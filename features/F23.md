# F23 — Autenticación local, MFA, sesiones y RBAC

> Ficha de implementación SDD (7 pasos).
> Peso máximo permitido: 8 KB.

---

## Objetivo

Incorporar autenticación local con contraseñas Argon2id, sesiones seguras, CSRF, MFA TOTP y autorización por roles para que la aplicación pueda operar en una LAN interna con datos reales sin depender de SSO.

## Alcance

- Usuarios locales individuales con roles `OPERADOR`, `AUDITOR`, `ADMIN`.
- Contraseñas con Argon2id; sin texto plano ni hashes reversibles.
- Login/logout con sesiones opacas en base de datos.
- Cookie `HttpOnly`, `Secure`, `SameSite=Lax`.
- Expiración idle 30 minutos y absoluta 8 horas; rotación al autenticar.
- CSRF token por sesión para todo estado modificable.
- MFA TOTP obligatorio para ADMIN y AUDITOR; recovery codes de un solo uso; sin SMS.
- Bootstrap del primer ADMIN mediante CLI interactivo.
- CLI para crear usuarios, resetear contraseña y desactivar cuentas.
- RBAC por ruta y acción; denegación por defecto.
- Registro mínimo de eventos de autenticación en `security_events`.
- Pantallas de login y MFA coherentes con el diseño actual.
- Tests de autenticación, autorización, CSRF, MFA y fuerza bruta.

## Fuera de alcance

- SSO/LDAP/OAuth; se deja interfaz preparada para el futuro.
- Autorregistro y recuperación por email.
- SMS como segundo factor.
- Administración web completa de usuarios; v1 usa CLI.
- Retención, backups y cifrado de base: F25/F26/F27.
- Hardening HTTP completo: F24.

## Clarificación y ambigüedades resueltas

> **Paso 3 SDD: Clarificación**

- [x] **Despliegue:** LAN interna, HTTPS por reverse proxy, sin Internet directo.
- [x] **Identidad:** cuentas locales; sin SSO/LDAP por ahora.
- [x] **Roles:** OPERADOR, AUDITOR, ADMIN.
- [x] **MFA:** TOTP obligatorio para ADMIN/AUDITOR; OPERADOR no obligatorio inicialmente.
- [x] **Bootstrap:** un único ADMIN por CLI interactivo; sin contraseña por defecto.
- [x] **Sesiones:** opacas, con revocación en servidor; idle 30 min, absoluta 8 h.
- [x] **CSRF:** obligatorio en POST/PUT/PATCH/DELETE autenticados.
- [x] **Rate limiting:** login 5/min por IP+usuario y bloqueo temporal tras 5 fallos.
- [x] **Secretos MFA:** cifrados con `APP_ENCRYPTION_KEY`; recovery codes hasheados.
- [x] **Usuarios:** alta/reset/desactivación por CLI; sin autorregistro.

## Criterios de aceptación

- [ ] Sin sesión, las rutas privadas redirigen a login o devuelven 401/403 según API/HTML.
- [ ] Login válido crea sesión; inválido no revela si el usuario existe.
- [ ] Contraseñas se almacenan con Argon2id y nunca se registran.
- [ ] ADMIN/AUDITOR deben enrolar y usar TOTP; OPERADOR puede iniciar sin MFA.
- [ ] Recovery codes funcionan una sola vez.
- [ ] CSRF faltante o inválido devuelve 403.
- [ ] Matriz RBAC testeada: OPERADOR, AUDITOR y ADMIN.
- [ ] Sesiones expiran/rotan/revocan correctamente.
- [ ] Primer ADMIN se crea por CLI; no existe contraseña por defecto.
- [ ] `uv run pytest` y `./init.sh` pasan al 100%.

## Planificación técnica y arquitectura

- **Modelos:** `Usuario`, `Sesion`, `CodigoRecuperacion`, `SecurityEvent`.
- **Contraseñas:** `argon2-cffi` (`PasswordHasher`).
- **Sesiones:** token `secrets.token_urlsafe(32)`, hash SHA-256 en DB, cookie opaca.
- **CSRF:** token aleatorio por sesión, hash en DB, header `X-CSRF-Token` o campo de formulario.
- **MFA:** TOTP RFC 6238 con HMAC-SHA1, ventana ±1 y control de replay; secreto cifrado con Fernet (`cryptography`).
- **Dependencias:**
  - `APP_ENCRYPTION_KEY` para secretos MFA.
  - `COOKIE_SECURE` (default true; false solo tests/dev HTTP).
  - `SESSION_IDLE_MINUTES`, `SESSION_ABSOLUTE_HOURS`.
- **Rutas públicas:** `/health`, `/login`, `/mfa` (sesión pendiente), `/static`.
- **Rutas privadas:** todo el resto con `require_web_user` o `require_api_user`.
- **RBAC:** dependencias `require_web_roles(...)` y `require_api_roles(...)`.
- **CLI:** `python -m ventas_app.cli admin-bootstrap|user-create|user-reset-password|user-disable`.
- **Migración:** nuevas tablas vía `create_all`; no alterar ventas.
- **Tests existentes:** fixture `client` autenticado como ADMIN de prueba con sesión directa y header CSRF; tests de seguridad usan cliente anónimo.

- CSRF ausente/incorrecto/correcto.

- Bootstrap único y CLI sin exponer contraseña en argumentos.
- Logs sin contraseñas, tokens, TOTP ni CSRF.

## Riesgos y dependencias

- Agrega dependencias pequeñas: `argon2-cffi`, `cryptography`, `python-multipart`.
- Requiere bootstrap operativo antes del primer uso.
- Si se ejecutan múltiples workers, el rate limit en memoria debe moverse a un almacén compartido; v1 LAN usa un worker o rate limit del proxy.
- No implementa SSO; la interfaz de autenticación debe quedar desacoplada.
