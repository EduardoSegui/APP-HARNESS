# F17 — Régimen de afiliación, CUIL y aportes estimados

> Ficha de especificación y planificación de acuerdo al ciclo SDD (7 pasos).
> Peso máximo permitido: 8 KB.

---

## Objetivo

Diferenciar el alta de un afiliado **Particular** de un **Desregulado** (relación de dependencia o monotributo), capturar el CUIL y descontar del total el aporte estimado que financia la obra social. Esto completa la ingeniería comercial del producto y permite calcular la cuota neta que paga el afiliado.

## Alcance

- Campo `regimen_afiliacion`:
  - `PARTICULAR`: paga el total bonificado.
  - `RELACION_DEPENDENCIA`: aportes por descuento de haberes.
  - `MONOTRIBUTO`: aporte mensual declarado.
- `cuil_titular` obligatorio para regímenes desregulados, con formato de 11 dígitos.
- `aporte_estimado` en ARS: monto declarado por el operador para desregulados; `0` para particulares.
- Nuevo desglose persistido: `aporte_estimado` y `precio_total` como **diferencia neta a pagar**.
- Fórmula:
  ```text
  subtotal_base = precio_titular + adherentes × precio_adherente
  descuento_monto = round_half_up(subtotal_base × descuento_porcentaje / 100)
  base_bonificada = subtotal_base - descuento_monto
  aporte_estimado = monto declarado (0 en PARTICULAR)
  precio_total = max(0, base_bonificada - aporte_estimado)
  ```
- Regla `R8 — Aportes y régimen` en el Auditor MCP:
  - Valida régimen, CUIL y aporte.
  - Observa si el aporte supera la base bonificada.
  - Observa si un desregulado no tiene CUIL o si un particular tiene aporte > 0.
- Panel, comprobante y detalle muestran régimen, CUIL enmascarado y aporte.

## Fuera de alcance

- Integración real con ANSES, ARCA/AFIP, SIRADIG o liquidación de haberes.
- Validación del dígito verificador del CUIL.
- Cálculo automático de aportes por escala o categoría; v1 usa monto declarado.
- Facturación, cobro o conciliación de aportes.
- Historia laboral o recategorizaciones.

## Clarificación y ambigüedades resueltas

> **Paso 3 SDD: Clarificación**

- [x] **Regímenes:** → **Decisión:** Particular, Relación de dependencia y Monotributo.
- [x] **Origen del aporte:** → **Decisión:** en v1 el operador informa un aporte estimado en ARS; la integración real queda fuera de alcance.
- [x] **Fórmula:** → **Decisión:** el aporte se resta después del descuento comercial y el total nunca es negativo.
- [x] **CUIL:** → **Decisión:** obligatorio para desregulados, 11 dígitos; no se valida dígito verificador en v1.
- [x] **Particular:** → **Decisión:** aporte siempre 0; si envían otro valor, la API responde 422.
- [x] **Ventas históricas:** → **Decisión:** se migran como `PARTICULAR` con aporte 0.

## Planificación técnica y arquitectura

- **Modelo `Venta`:**
  - `regimen_afiliacion: String(30) NOT NULL DEFAULT 'PARTICULAR'`
  - `cuil_titular: String(11) | None`
  - `aporte_estimado: Integer NOT NULL DEFAULT 0`
- **Schemas:**
  - `RegimenAfiliacion` enum.
  - `VentaIn`/`VentaUpdateIn`: `regimen_afiliacion`, `cuil_titular`, `aporte_estimado`.
  - Validador contextual: CUIL obligatorio si no es particular; aporte 0 si particular; aporte <= base bonificada.
- **Pricing:** `calcular_cotizacion` recibe régimen, CUIL y aporte; devuelve `CotizacionDetalle` ampliado con `aporte_estimado`.
- **Auditor:** `validar_r8_regimen_aportes(detalle)`.
- **Migración:** columnas nuevas con defaults; filas históricas como particular.
- **UI:** selector de régimen, CUIL y aporte condicionales; máscara de CUIL en panel.

## Tests y casos borde

- Particular: aporte 0 y total = base bonificada.
- Relación de dependencia con CUIL y aporte válidos.
- Monotributo con aporte igual a la base → total 0.
- Aporte mayor a la base → `422`.
- Desregulado sin CUIL → `422` y R8 observa.
- Particular con aporte > 0 → `422`.
- Venta histórica migrada como particular.
- Edición de régimen y aporte con recálculo.
