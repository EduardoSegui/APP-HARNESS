# F30 — Administración excepcional de ventas

> Ficha de implementación SDD. Peso máximo: 8 KB.

## Objetivo

Permitir que un ADMIN reabra una venta aprobada para corregirla con reauditoría y que dé de baja lógica una venta sin destruir historial, legal holds ni backups.

## Alcance

- Botón/acción ADMIN para reabrir una venta `APROBADA`.
- Aviso explícito: la edición la devuelve a `PENDIENTE_VERIFICACION` y requiere nueva auditoría.
- Motivo obligatorio y confirmación.
- Cambio de estado + evento de linaje con actor real.
- Baja lógica: `eliminada_en`, `eliminada_por`, `motivo_baja`.
- Motivo y confirmación; solo ADMIN.
- La venta dada de baja desaparece de panel, tablero, exportaciones y MCP.
- La fila y su linaje se conservan.
- Legal hold bloquea la baja.
- Tests de RBAC, versión, estado, auditoría y filtrado.

## Fuera de alcance

- Borrado físico de ventas o eventos.
- Edición directa de una venta aprobada sin reabrirla.
- Playwright/video demo (F31).
- Rediseño del wizard.

## Clarificación

- [x] Editar una aprobada siempre reabre y reaudita; no se mantiene `APROBADA`.
- [x] “Eliminar” significa baja lógica, no `DELETE` físico.
- [x] Solo ADMIN puede reabrir o dar de baja.
- [x] Motivo y confirmación son obligatorios.
- [x] Un legal hold activo bloquea la baja.
- [x] La venta dada de baja queda fuera de listados y métricas, pero se conserva para auditoría.

## Seguridad y privacidad

- Datos: venta/PII; la baja no anonimiza ni borra.
- Rutas: `POST /api/ventas/{id}/reabrir` y `DELETE /api/ventas/{id}` solo ADMIN; botones ocultos a otros roles.
- Abuso: CSRF, versión obligatoria, legal hold, motivo, rate limit.
- Logs: actor real y evento de negocio; sin duplicar PII en logs.
- Auditoría: evento de reapertura/baja; legal hold y linaje conservados.

## Criterios de aceptación

- [x] ADMIN reabre una aprobada → estado `PENDIENTE_VERIFICACION`, evento y versión.
- [x] Sin motivo o sin confirmación → 422/400, sin cambios.
- [x] OPERADOR/AUDITOR → 403.
- [x] Versión obsoleta → 409 sin cambios.
- [x] Baja lógica → venta fuera de panel/métricas/export/MCP, fila y eventos intactos.
- [x] Legal hold activo bloquea baja.
- [x] `./init.sh` y tests verdes.

## Riesgos

La baja lógica debe excluirse de todos los agregados para no distorsionar métricas. No debe existir endpoint de borrado físico. El desbloqueo de una venta aprobada debe dejar rastro explícito.
