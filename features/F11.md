# F11 — Feature packets e intake

## Objetivo

Agregar una ficha autocontenida por feature y el protocolo de planificación que permita abrir trabajo nuevo sin inventar alcance ni leer el PRD completo.

## Alcance

- Plantilla `features/_TEMPLATE.md` con las secciones mínimas.
- Ficha `features/F11.md` como primer ejemplo real.
- Campo `packet` en `features.json` para F11 y para las features futuras.
- Protocolo de planificación en `.agent/rules.md`: si no hay pendientes, se escribe una ficha y recién después se construye.
- Actualización de `/sesion` para que no construya cuando el estado pide planificación.
- Validación automática de fichas en `scripts/contexto.py` (ya existe; se usa y se prueba con la ficha real).
- Tests de la plantilla, de la ficha de F11 y del flujo de planificación.

## Fuera de alcance

- No se reescriben fichas para F01–F10.
- No se modifica código de la aplicación (`src/ventas_app/`), base de datos, API ni UI.
- No se agrega RAG, búsqueda semántica ni carga automática de documentos.
- No se cambia el formato de `features.json` más allá del campo `packet`.

## Criterios de aceptación

- [ ] `features/_TEMPLATE.md` contiene todas las secciones requeridas por `scripts/contexto.py`.
- [ ] `features/F11.md` existe, pesa menos de 8 KB y contiene todas las secciones requeridas.
- [ ] `features.json` declara `"packet": "features/F11.md"` para F11.
- [ ] `.agent/rules.md` explica cómo planificar una feature nueva y que sin ficha no se construye.
- [ ] `contexto.py --check` valida la ficha y falla si falta una sección.
- [ ] `uv run pytest` y `./init.sh` pasan.

## Tests y casos borde

- Plantilla con todas las secciones requeridas.
- Ficha de F11 válida y dentro del cap de 8 KB.
- Feature con `packet` inexistente: `check` falla.
- Ficha sin una sección: `check` falla.
- Ficha de más de 8 KB: `check` falla.
- Planificación sin código: el protocolo no requiere modificar `src/`.

## Riesgos y dependencias

- Depende de F09/F10 (estado, caps y rotación) ya verificadas.
- Si la ficha se vuelve demasiado larga, pierde el beneficio; el cap de 8 KB lo limita.
- La ficha no reemplaza al PRD/ARQ: solo cita las secciones necesarias.
