# F24 — Hardening HTTP, errores seguros y anti-abuso

> Ficha de implementación SDD. Peso máximo: 8 KB.

## Objetivo

Endurecer la superficie HTTP de la aplicación para LAN: headers de seguridad, CSP compatible con el diseño actual, límites de entrada, rate limiting, bloqueo de auditorías concurrentes y errores que no filtren PII.

## Alcance

- Middleware de headers: CSP, `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`, `Cache-Control: no-store`, `X-Robots-Tag: noindex`.
- HSTS y `TrustedHost` configurables para HTTPS/reverse proxy.
- Deshabilitar `/docs`, `/redoc` y `/openapi.json` en producción.
- Límites: body 256 KB, 20 integrantes, `q` 100 caracteres, page size 100, export 5.000 filas/streaming.
- Rate limiting: login, alta/edición, auditoría, exportaciones y búsquedas.
- Lock/idempotencia para `POST /api/auditar`.
- Handler de `RequestValidationError` sin `input`/`ctx`/objetos completos.
- Eliminar `onclick` inline de la credencial y agregar JS externo.
- Logs de acceso sin query strings sensibles.
- Tests de headers, límites, rate limit, 422 sanitizado y auditoría concurrente.

## Fuera de alcance

- Autenticación/RBAC (F23).
- Cifrado/LLM/backups (F25/F26).
- Self-host de Tailwind/fuentes; se deja CSP compatible y pinning para F28.

## Riesgos

CSP puede bloquear CDN/fuentes si se configura mal; validar en navegador. Rate limit en memoria no escala a múltiples workers.

## Tests y casos borde

- Headers/CSP en HTML y API.
- 422 con tarjeta/DDJJ no devuelve valores.
- Límites de body, integrantes, búsqueda y export.
- Rate limit/login y lock de auditoría.
- `onclick` ausente y JS externo cargado.
