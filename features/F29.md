# F29 — Hardening de seguridad y datos

> Ficha de implementación SDD. Peso máximo: 8 KB.

## Objetivo

Corregir los riesgos críticos/altos detectados en la auditoría técnica antes de habilitar la administración excepcional de ventas y la demo automatizada.

## Alcance

- Evitar doble cifrado o pérdida de acceso a `ddjj_detalle` cuando `APP_ENCRYPTION_KEY` no coincide o cambia.
- Rate limit, contador y bloqueo de intentos fallidos de MFA.
- Redacción de DNI/CUIL/contacto en `venta_eventos` y en eventos de seguridad.
- Actor real (username) en eventos de venta; `mcp-auditor` para procesos sin usuario.
- `version` obligatoria en PUT para control optimista.
- Enmascarar CUIL/instrumentos de pago en la ficha de legajo.
- Tests de regresión y documentación operativa.

## Fuera de alcance

- Edición de ventas aprobadas y baja lógica; quedan en F30.
- Playwright/video; queda en F31.
- Cambios de UI de administración excepcional.

## Clarificación

- [x] No se usarán datos reales: todo dato de prueba/demostración será ficticio.
- [x] Un token cifrado que no descifra con la clave actual no se re-cifra silenciosamente.
- [x] El bloqueo MFA se aplica a la sesión pendiente y se registra sin PII.
- [x] Los eventos conservan códigos de regla; se redactan identificadores.
- [x] `version` obligatoria en edición, con compatibilidad explícita documentada.
- [x] La demo usará admin ficticio y TOTP generado por el script, sin Google Authenticator real.

## Criterios de aceptación

- [x] Un token de otra clave produce error seguro y no modifica la fila.
- [x] 5 intentos MFA fallidos revocan la sesión pendiente; el sexto no permite probar códigos.
- [x] Los eventos nuevos no contienen DNI/CUIL/email/teléfono; la anonimización redacta históricos.
- [x] Los eventos de alta/edición registran el username del usuario autenticado.
- [x] PUT sin `version` devuelve 422/428; versión obsoleta devuelve 409.
- [x] La ficha de legajo no muestra CUIL/instrumento completo.
- [x] `./init.sh`, suite y pruebas manuales verdes.

## Tests y casos borde

- Clave incorrecta/rotación; token corrupto.
- MFA incorrecto, replay, recovery usado y bloqueo.
- Redacción de DNI/CUIL/email/teléfono en eventos.
- PUT sin versión, versión obsoleta y concurrencia secuencial.
- Actor real en alta/edición.
- CUIL enmascarado en UI.
- Suite completa y `./init.sh`.

## Riesgos

El bloqueo MFA agresivo puede afectar usuarios legítimos; se aplica solo a la sesión pendiente y se documenta el reset. La redacción histórica de eventos debe ejecutarse solo en el flujo DSR con backup y confirmación.
