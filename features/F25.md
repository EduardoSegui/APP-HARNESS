# F25 — Protección de PII/salud, secretos, MCP y LLM

> Ficha de implementación SDD. Peso máximo: 8 KB.

## Objetivo

Minimizar y proteger datos personales y de salud, evitar filtraciones por logs/LLM/MCP y aislar secretos, manteniendo el proveedor local actual y una interfaz preparada para proveedores externos.

## Alcance

- Permisos: `.env` y DB `600`, directorio `700`, usuario de servicio dedicado.
- Cifrado de volumen/OS y cifrado de campos sensibles (`ddjj_detalle`, secreto MFA) con `cryptography`.
- DTOs/MCP por rol: no devolver salud/CUIL completo si no se necesita.
- Interfaz `LLMProvider`: local Ollama por defecto; externo deshabilitado.
- Habilitación externa solo ADMIN, auditada; API key en secreto/entorno.
- Payload externo solo conteos/códigos R1–R8; nunca salud, DNI, CUIL, domicilio, email, teléfono ni pagos.
- Redacción/allowlist de egress y fallback local.
- Entorno del subproceso MCP con allowlist; sin API keys.
- Reducir PII en `sessionStorage`; sin salud/pagos.
- Tests de fugas en errores, logs, prompts, MCP y archivos.

## Fuera de alcance

- SSO, retención automática y backups (F23/F26/F27).
- Migración a Postgres o SQLCipher.

## Riesgos

Cifrado de campos con búsquedas existentes (DNI/CUIL) requiere diseño cuidadoso; no cifrar claves de búsqueda sin índice ciego. No sobrecifrar en v1 más allá de salud/MFA.

## Tests y casos borde

- Archivos sin permisos de grupo/mundo.
- Prompt externo sin DNI/CUIL/salud.
- MCP sin claves en el entorno.
- sessionStorage sin salud/pagos.
- Fallback local ante error externo.
