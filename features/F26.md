# F26 — Durabilidad, backups, concurrencia e inmutabilidad

> Ficha de implementación SDD. Peso máximo: 8 KB.

## Objetivo

Evitar pérdida de datos y conflictos silenciosos: backups cifrados verificables, SQLite durable, control optimista y evidencia de auditoría inmutable.

## Alcance

- SQLite: WAL, `busy_timeout`, `synchronous`, `foreign_keys`, `integrity_check`.
- Backup diario con `sqlite3.Connection.backup`.
- Cifrado obligatorio; checksum; 7 diarios, 4 semanales y 1 semanal offline.
- Clave fuera del almacenamiento de backups; permisos `600`.
- Restore mensual en base temporal + smoke; RPO 24 h, RTO 8 h.
- Scripts CLI/systemd; restore solo ADMIN/custodio; sin endpoint web.
- `Venta.version` para control optimista; `PUT` con `409`.
- `venta_eventos` append-only con triggers; hash chain si es simple.
- Tests de backup/restore, integridad, concurrencia y eventos.

## Fuera de alcance

- Backups a nube o HA.
- Migración a Postgres.

## Riesgos

Restore puede sobrescribir datos; usar siempre copia previa, validación y modo mantenimiento. SQLite en un solo host no elimina el riesgo físico; backups fuera del servidor son obligatorios.

## Tests y casos borde

- Backup cifrado, checksum e integridad.
- Restore a DB temporal y smoke.
- Retención 7+4+1.
- PUT obsoleto 409.
- Trigger impide UPDATE/DELETE de eventos.
