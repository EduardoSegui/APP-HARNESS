# F12 — Plan de diseño: Legajo de alta

> Skill usada: `frontend-design` (anthropics/skills, commit `e4bb5d960d87126ff3b3a8af1a104b7db67560ba`).
> Este documento es el plan previo a la implementación. No contiene código de producción.

## 1. Brief

**Producto:** aplicación interna de ventas de obra social. Dos superficies:

- **Wizard de alta:** tres etapas (titular y grupo familiar, domicilio, plan y cotización) y comprobante final.
- **Panel de ventas:** mesa de entradas con estados, observaciones, auditoría con IA y traza MCP.

**Audiencia:** agentes y supervisores de ventas en una oficina. Español argentino. Escritorio primero, móvil usable.

**Trabajo principal:** cargar una venta con confianza y detectar rápido qué ventas necesitan revisión.

**Restricciones:** Jinja2 + Tailwind CDN + JavaScript vanilla, sin build. Hay que preservar IDs, `data-*`, nombres de campos, endpoints y los textos que verifican los tests funcionales.

## 2. Dirección visual

**Concepto: “Legajo de alta” / “Mesa de entradas”.**

El wizard es un legajo que se va armando: tres solapas, una hoja de formulario y un resumen que se completa. El panel es la mesa donde llegan los legajos y se sellan como pendientes, aprobados u observados.

La identidad sale del papeleo de una obra social —credenciales, cartillas, sellos, planillas—, no de un dashboard SaaS. El elemento audaz es el **rail de solapas + el sistema de sellos**; el resto queda quieto: superficies planas, reglas finas, tipografía clara.

## 3. Tokens

### Color (6 colores base)

| Token | Hex | Uso |
|---|---|---|
| `--tinta` | `#16211E` | Texto principal, bordes fuertes, tablas. |
| `--papel` | `#F2F4EF` | Fondo de página, papel frío de archivo. |
| `--verde` | `#1F5A4D` | Acción primaria, aprobado, foco. |
| `--vino` | `#7A2E3B` | Observado, errores, sellos de atención. |
| `--mostaza` | `#B5852F` | Pendiente, advertencia. |
| `--blanco` | `#FFFFFF` | Hojas, inputs, superficies elevadas. |

Tonos derivados con `color-mix` (sin hex nuevos):

- `--verde-suave`: `color-mix(in srgb, var(--verde) 12%, var(--blanco))`.
- `--vino-suave`: `color-mix(in srgb, var(--vino) 10%, var(--blanco))`.
- `--mostaza-suave`: `color-mix(in srgb, var(--mostaza) 16%, var(--blanco))`.
- `--linea`: `color-mix(in srgb, var(--tinta) 14%, var(--papel))`.

Contraste: tinta sobre papel ≈ 13:1; blanco sobre verde ≈ 7:1; vino sobre blanco ≈ 8:1. Para texto de pendiente no usar mostaza puro: usar `color-mix(in srgb, var(--mostaza) 45%, var(--tinta))` sobre `--mostaza-suave`.

Evitar: crema + terracota, casi negro + acento ácido, gradientes decorativos, tarjetas idénticas con sombra gris.

### Tipografía

| Rol | Fuente | Pesos | Por qué |
|---|---|---|---|
| Display, títulos, wordmark | **Bricolage Grotesque** | 500, 600, 700 | Grotesca humanista con detalles propios; administrativa sin ser genérica. |
| Cuerpo, UI, tablas | **Public Sans** | 400, 500, 600 | Legible, cívica, pensada para servicios; buena para formularios densos. |

Escala: 12 / 14 / 16 / 18 / 24 / 32 / 44 px. Cuerpo 16 px, línea 1.55. Títulos 1.1. Ancho de lectura ≤ 68ch en formularios y ≤ 80ch en texto corrido. Precios e IDs con `font-variant-numeric: tabular-nums`; no usar monospace para etiquetas.

Sin etiquetas en mayúsculas, sin “eyebrows” tracked-out, sin acentuar una sola palabra del titular.

### Espaciado, radios y sombras

- Base 4 px; escala 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64.
- Hoja: radio 14 px. Solapas: 10 px arriba. Inputs: 8 px. Sellos: 4 px con doble borde.
- Sombra única y baja: `0 1px 0 color-mix(in srgb, var(--tinta) 8%, transparent)`. No sombra difusa en cada tarjeta.
- Reglas de 1 px para separar secciones; no cajas dentro de cajas.

## 4. Layout

### Shell compartido

- Ancho máximo 1180 px; padding 24 px móvil / 32 px escritorio.
- Cabecera: wordmark “Obra Social” + “Altas”, navegación “Nueva venta” / “Panel”, indicador de uso interno.
- La navegación activa se marca con una solapa inferior, no con una píldora.
- Footer mínimo: “Uso interno. Los datos se guardan al confirmar la venta”.

### Wizard — escritorio

```text
┌──────────────────────────────────────────────────────────────┐
│ Obra Social   Altas      Nueva venta   Panel       Uso interno│
├───────────────┬──────────────────────────────────────────────┤
│ LEGAJO        │  Paso 1 de 3   Titular y grupo familiar      │
│               │                                              │
│ ┌ 01 Titular ┐│  ┌────────────────────────────────────────┐  │
│ │ 02 Domicilio││  │ Datos del titular                      │  │
│ │ 03 Plan     ││  │ [Nombre]        [Apellido]             │  │
│ └─────────────┘│  │ [DNI]           [Fecha de nacimiento]  │  │
│               │  │ [Email]         [Teléfono]             │  │
│ Resumen       │  └────────────────────────────────────────┘  │
│ Ana Pérez     │                                              │
│ 2 adherentes  │  ┌ Grupo familiar ────────────────────────┐   │
│ Plan —        │  │ [Adherente 1]                         │   │
│               │  └────────────────────────────────────────┘   │
│               │                            [Continuar]        │
└───────────────┴──────────────────────────────────────────────┘
```

- Rail izquierdo de 260 px, sticky en escritorio. Solapas verticales; la activa se conecta visualmente con la hoja.
- Hoja de formulario a la derecha, una sola columna interna; campos en grilla de 2 columnas solo cuando el ancho lo permite.
- Resumen del legajo en el rail: titular, cantidad de adherentes, plan elegido. En el paso 3 se convierte en la cotización completa.
- La cotización no es una tarjeta genérica: es una “credencial” con borde izquierdo verde, total grande y desglose en líneas.

### Wizard — móvil

- El rail pasa a un stepper horizontal de 3 solapas con scroll si hace falta.
- El resumen se colapsa debajo del formulario, antes de las acciones.
- Una columna; botones de ancho completo o alineados a la derecha con mínimo 44 px de alto.
- Sin scroll horizontal en el formulario.

### Panel — escritorio

```text
┌──────────────────────────────────────────────────────────────┐
│ Obra Social   Altas      Nueva venta   Panel       Uso interno│
├──────────────────────────────────────────────────────────────┤
│ Mesa de entradas                           [Auditar pendientes]│
│ Ventas recientes   12 registradas                            │
│  Pendientes 3      Aprobadas 7      Observadas 2             │
│ ┌──────────────────────────────────────────────────────────┐ │
│ │ #012  Ana Pérez     Integral   3   $182.000  ⏳ Pendiente │ │
│ │       DNI 30111222                              Observac. │ │
│ └──────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────┘
```

- Cabecera de mesa: título, contador y acciones. El botón de auditar es primario (verde); “Nueva venta” es secundario (borde).
- Franja de sellos con los tres estados y sus conteos; no tarjetas grandes de estadísticas.
- Tabla dentro de una hoja, con encabezado de planilla y filas separadas por reglas. El estado va en un sello a la izquierda o en una columna fija, no en una píldora genérica.
- Observaciones en una celda de ancho controlado, con `white-space: pre-line`.
- Acta de auditoría: `<details>` con encabezado de acta, conteos, narrativa y tabla de traza. Al abrir, se resalta el borde, sin animación aparatosa.

### Panel — móvil

- La tabla se convierte en filas apiladas; cada celda muestra su etiqueta con `data-label`.
- El sello de estado queda arriba de la fila, junto al ID y el total.
- Las acciones se mantienen visibles; el acta de auditoría ocupa el ancho completo.

## 5. Componentes

- **Solapa de paso:** número + nombre, borde superior redondeado. Activa: fondo blanco, borde verde, “fold” de 1 px. Completada: sello pequeño de check. Pendiente: texto atenuado.
- **Hoja:** superficie blanca, borde 1 px `--linea`, radio 14 px, sin sombra difusa.
- **Campo:** label visible arriba, input 44 px, borde `--linea`, foco con anillo verde de 2 px. Error: borde vino + mensaje debajo, no solo color.
- **Sello de estado:** rectángulo con doble borde, ícono simple (reloj, check, alerta) + palabra. Pendiente mostaza, aprobada verde, observada vino. Texto siempre presente; el color no es el único portador.
- **Plan:** tabla/cartilla comparativa de 3 columnas en escritorio (Plan, titular, adherente, cobertura) con radio; en móvil, filas apiladas. La selección se marca con un sello “Elegido” y borde verde, no con una card que cambia de color solamente.
- **Credencial de cotización:** borde izquierdo verde, total grande, desglose tabular; en el comprobante se reutiliza como “constancia”.
- **Botón primario:** verde, texto blanco, radio 8 px. Secundario: blanco con borde. Terciario: texto subrayado. Sin “→” decorativo.
- **Estado vacío:** bandeja de archivos simple (SVG de línea) + texto claro + CTA; sin tarjeta genérica centrada.
- **Acta de auditoría:** `<details>` con summary tipo solapa; conteos como sellos; narrativa en bloque con borde; traza en tabla compacta.

## 6. Movimiento

- Un solo momento orquestado: al cambiar de paso, la hoja entra con `opacity` + `translateY(6px)` en 180 ms; la solapa activa cambia su borde. Nada más.
- Al abrir el acta, el `<details>` nativo hace el trabajo; solo se resalta el borde.
- `@media (prefers-reduced-motion: reduce)` desactiva transiciones y transformaciones.
- Hover solo en filas, botones y solapas; no en cada bloque.

## 7. Accesibilidad

- Foco visible en todos los interactivos: `outline: 2px solid var(--verde); outline-offset: 2px`.
- Labels asociados; errores con texto, no solo borde. Mantener `aria-live` en el error general.
- Tabla con `<th scope="col">`; en móvil, `data-label` para no perder contexto.
- Contraste revisado; estados con texto + ícono, no solo color.
- Botones de mínimo 44 px; navegación por teclado; sin traps.
- Respetar `prefers-reduced-motion` y `prefers-contrast` si es razonable.

## 8. Copy

- Español argentino, sentence case, verbos activos.
- Conservar los textos que los tests funcionales exigen: “1. Titular y grupo familiar”, “2. Domicilio”, “3. Plan y cotización”, “Datos del titular”, “Grupo familiar”, “Resumen de cotización”, “Todavía no hay ventas registradas”, “Cargar primera venta”, “Panel de ventas”.
- Estados visibles: “Pendiente”, “Aprobada”, “Observada”; el `data-estado` sigue guardando el enum para JS y tests.
- Botones: “Continuar”, “Volver”, “Confirmar venta”, “Auditar pendientes”, “Nueva venta”. Sin flechas decorativas.
- Errores: explican qué pasó y cómo corregirlo; no piden disculpas.

## 9. Revisión contra los defaults de frontend-design

| Default detectado | Decisión |
|---|---|
| Crema + terracota | Descartado. Papel frío verdoso + verde profundo + vino/mostaza. |
| Casi negro + acento ácido | Descartado. Tinta verde-negra, acentos muted. |
| Broadsheet con reglas finas y columnas densas | Descartado como estructura. Usamos una app de dos columnas con hoja, no un periódico. |
| Kit de tarjetas SaaS idénticas | Descartado. Hoja única, solapas, sellos y tabla; no card soup. |
| Eyebrows en mayúsculas, meta con “·”, labels monoespaciados, “→” en botones | Descartados. Sentence case, Public Sans, sin flechas decorativas. |
| Números 01/02/03 decorativos | Se usan solo porque los pasos son una secuencia real. |
| Hero con número grande + stats + gradiente | Descartado. El “hero” es la tarea actual: el legajo o la mesa de entradas. |

La audacia se concentra en el rail de solapas y los sellos. El resto es disciplina: tipografía, reglas, espacio y estados claros.

## 10. Implementación

- Crear `src/ventas_app/static/css/design.css` con tokens, shell, componentes y media queries.
- Enlazarlo desde `base.html` después de Tailwind; cargar Bricolage Grotesque y Public Sans con `font-display: swap`.
- Mantener Tailwind CDN y usarlo para layout/espaciado; usar clases semánticas para color, tipografía y componentes.

- Ajustar `auditoria.js`: mapa de etiquetas amigables y clases de sello; conservar `data-estado` y `data-observaciones`.
- Actualizar aserciones visuales de `tests/test_wizard.py` y `tests/test_panel.py`; agregar `tests/test_ui_design.py` para tokens, foco y reduced motion si aporta valor.
- Verificar con `./init.sh`, `uv run pytest` y revisión manual en 360/768/1280 px.

## 11. Riesgos y preguntas abiertas

- **Red:** Tailwind y Google Fonts por CDN. Si el entorno debe funcionar offline, self-hostear fuentes y Tailwind.
- **Especificidad:** Tailwind + CSS propio puede pelear; usar variables y clases semánticas, evitar `!important`.
- **Tests:** las aserciones de clases visuales cambian; las de comportamiento no. Cualquier cambio de texto exigido por tests se justifica.
- **JS:** el mapa de estados de `auditoria.js` debe actualizarse junto con los sellos; probar la auditoría en vivo.
- **Revisión visual:** no hay navegador automatizado en el repo; la aceptación visual final es manual con checklist y, si se puede, capturas.
- **Fuentes:** Bricolage Grotesque y Public Sans deben verificarse en Google Fonts antes de implementar; si no están disponibles, elegir alternativas con la misma intención.
